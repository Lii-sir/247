# Single-Node DDP Implementation Plan

The user approved GPU-list selection and per-device batch size. Extend the CCD
CLI using one spawned process per selected GPU; retain the single-device path.

- [x] Parse and validate `--device 0 1`, preserving auto/cuda/cpu. Inference
  accepts one device. Reject duplicate, negative, unavailable and mixed devices.
- [x] Record world size and global batch; divide image budgets by global batch.
  Resume preserves per-device batch and world size; GPU indices may change.
- [x] Share the optimization loop in `ccd_distributed.py`. Use DDP and separate
  distributed samplers for normal and auxiliary images, dropping incomplete
  global batches. Advance sampler epochs independently. Freeze teacher and
  normalization parameters before DDP. Reduce reported losses across ranks.
- [x] Prepare assets and global teacher statistics once in the parent; write
  checkpoints only on rank zero and calibrate/evaluate once after workers exit.
  Use NCCL when available and Gloo otherwise, with a local file rendezvous.
  Preserve local student BatchNorm with rank-zero buffers in checkpoints.
- [x] Test argument validation, budgets, sampling, single-device compatibility,
  real two-process CPU training/restore, distributed gradient equivalence, and
  coordinated nonfinite-loss failure. Run the existing end-to-end smoke test.
- [x] Document commands, per-card batch, LR policy, resume constraints, platform
  backend differences, and limits of verification on one physical GPU.

The CLI scope does not add multi-node launching or make the independent
Lightning/Engine entry point DDP-ready. Multi-process interruption retains the
last successfully written checkpoint, unlike the single-process interrupt save.
